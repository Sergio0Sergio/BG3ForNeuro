# 02 — Маршрут клика по диалогу и контракт server↔client

Type: grilling
Status: resolved
Blocked by: 01

## Question

По фактам из тикета 01 «BG3SE: как программно выбрать вариант диалога (server vs client)»: выбрать маршрут клика и спроектировать контракт.

- **Маршрут**: server-only, если 01 показал рабочий серверный способ; иначе — клиентский `ClientAutoselectExecutor` (client Lua ищет элемент по `option_index`, подсвечивает и кликает).
- **Контракт**: как команда «выбрать вариант N» проходит C# → server-Lua → (client-Lua) → UI; как `option_index` (порядок в окне) маппится на элемент; чем подтверждается успех (результат-ответ vs следующий state); поведение при отсутствии клиента (fallback X1: `not_supported` + warning) и при выходе из диалога/торговли.
- **Тайминги/идемпотентность**: клик не должен гоняться повторно explore/combat-тиками; состояние «диалог открыт» читается из `bg3_to_neuro.json`.

Домен-термины уточняются здесь же (domain-modeling): «option_index», «клиентский контекст (Client)», «cross-OS сообщение» — при необходимости фиксируются в `CONTEXT.md`.

## Answer

Решения (раунд grilling, ответы пользователя):

- **Q1 (маршрут/режим) = (а)**: только авто-клик на клиентском контексте. Человек ничего не нажимает; режим «подтверди клавишей» не делаем (соз-е при необходимости).
- **Q2 (как ищется кнопка) = (б)**: клиент получает `option_index` **и** `option_text`. Первичный поиск — по `option_index` (= порядок кнопки в окне диалога); при сбое/несовпадении нумерации — подстраховка по тексту варианта.
- **Q3 (как узнаём результат) = (а)**: доверяем следующему состоянию. Клик шлётся fire-only, без подтверждения обратно; успех виден по новому state диалога (другая строка). Отдельная подтверждающая петля не вводится.
- **Q4 (что при неудаче) = (а)**: честный `not_supported` + warning — «Neuro никогда не остаётся без канала» (X1). Клиента нет / диалог закрыт / торговля — не молчим, отвечаем кодом-ошибкой.

**Итоговый маршрут**: C# → action-файл (`select_dialogue_option`) → server-Lua → **NetChannel**-сообщение (`Ext.Net.CreateChannel` + `SendToClient`, payload = `option_index` + `option_text`) → client-Lua (`Ext.UI`: обход Noesis-дерева окна диалога, поиск по индексу, fallback по тексту, клик `:Execute()`/`Subscribe("Click")`) → игра сдвигает реплику → следующий `bg3_to_neuro.json` (диалоговый state).
Идемпотентность: клик привязывается к текущей реплике (голосование в серверном Lua, повторный тик не перекликивает); устаревший клик по уже закрытому диалогу → `not_supported` + warning.

Домен-термины: `option_index`, клиентский контекст, cross-OS сообщение — зафиксированы в `CONTEXT.md`.

Контекст-указатель: map.md «Decisions so far» — строка тикета 02; маршрут готов к имплементации (вне карты).
