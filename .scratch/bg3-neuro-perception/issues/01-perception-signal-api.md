# 01 — Какие сигналы движка/BG3SE отдают «восприятие» сущности партией?

Type: research
Status: resolved
Blocked by: none

## Question

Какие сигналы доступны из Lua-контекста мода (BG3SE), чтобы определить, **воспринимает ли партия** данную сущность прямо сейчас — и что из этого годится как источник истины для трёхсостояния `visible`/`known`/`unknown`?

Требуется отчёт по кандидатам: точное имя API/компонента, как вызывать, что возвращает, ограничения. Интересуют, как минимум:

- прямая видимость / line-of-sight (`CanSee`-подобные Osi-предикаты, рейкасты, vision-компоненты);
- скрытность и обнаружение (невидимость, stealth, `IsInvisible`/`IsHidden`, shroud/туман движка);
- осведомлённость/память движка (знает ли партия о сущности: combat-aware, fog-of-war для конкретной сущности);
- чем отличаются клиентский и серверный контексты (мод живёт в обоих);
- стоимость вызова на сущность за тик (для многих сущностей).

## Constraints

- Мод живёт в двух контекстах (`CONTEXT.md`): серверный (эмиссия/приём команд) и клиентский (UI). Сигнал должен работать там, где рождается состояние.
- `Osi` — ленивый резолвер: пробовать `Osi.X ~= nil` нельзя, только прямой `pcall`-вызов (правило AGENTS.md).
- Нужно покрыть и бой, и эксплорейшн.

## Deliverable

`research/01-perception-signal-api.md`: таблица кандидатов (сигнал → что даёт → ограничения → рекомендация), со ссылками на первоисточники (BG3SE source/docs). Плюс краткий вердикт: есть ли один универсальный сигнал или нужна композиция.

## Verification

- Каждый заявленный API подтверждён первоисточником (код BG3SE / документация), а не догадкой.
- Явно отмечено, где сигнала нет и потребуется приближение (связано с решением Q7 карты).

## Answer

Отчёт: [`research/01-perception-signal-api.md`](../research/01-perception-signal-api.md).

- **Одного универсального сигнала нет.** Рекомендация — композиция.
- **Основной кандидат:** `Osi.CanSee(source, target)` → int bool (`Osi.lua:216`), OR по членам партии; дешёвая альтернатива `Osi.CanSeeCached` (`Osi.lua:221`).
- **Геометрия отдельно:** `Osi.HasLineOfSight(source, target)` → 1/0 (`Osi.lua:1373`) — чистый LOS, без статусов.
- **Объясняющие статусы:** `Osi.IsInvisible` (`Osi.lua:1686`), `IsInvisibleByScript` (`Osi.lua:1690`), `Osi.HasActiveStatus(uuid, "SNEAKING"/"INVISIBLE")` (`Osi.lua:1340`). Эталон движка — `brawl_Utils.lua:266 isVisible` (статусы, **без** геометрии).
- **Не то:** `Osi.ShroudRender`/`NETMSG_SHROUD_UPDATE` — туман **карты**, не видимость сущности.
- **Отложено:** серверный viewshed (`Sight`/`ServerViewshedParticipant`/`ServerSightAggregatedData`) — авторитетен, но чтение из Lua не подтверждено.
- **Открыто для 02:** точная семантика `CanSee` (свет/конусы/высота/скрытность), различие клиент/сервер и цена на N×M. Все Osi-ссылки сверены построчно с `bg3se\Osi.lua`; AI-ссылки — с `bg3se\brawl_Pick.lua:293,551`, `bg3se\brawl_Actions.lua:339`.
