# bg3-neuro-perception — карта: честное восприятие (fair perception)

Tracker: local markdown (`.scratch/<effort>/`), per `docs/agents/issue-tracker.md` → «Wayfinding operations». Эта карта — **индекс**: решения живут в тикетах, здесь только гist + ссылка.

## Destination

**Спек честного восприятия**: мод эмитит состояние, содержащее только воспринятое партией, а роутер честно отказывает в действиях по невоспринятой цели. Контракт поведения для Neuro: агент никогда не получает знание засады (сущности сквозь туман/стены/скрытность).

Скоуп по итогам грайлинга: **эксплорейшн + бой**; **все сущности** под единым принципом; **партия всегда известна**; представление — **бинарная модель v1** (решено при контракте, тикет 03): `visible` — на экране → эмитится с текущей позицией; не видна → не эмитится вовсе; **память/`known`/`last_seen` вырезаны целиком** (стейл-координата врёт); восприятие гасит и **эмиссию, и действия** (честный отказ).

## Decisions so far

<!-- индекс: одна строка на закрытый тикет -->

- **perception-signal-api** (research, ticket `01`, 2026-09-20): одного сигнала «восприятия партии» нет — нужна **композиция**. Основной кандидат `Osi.CanSee` (+`CanSeeCached`) OR по партии; геометрия отдельно — `Osi.HasLineOfSight`; объясняющие статусы — `IsInvisible`/`IsInvisibleByScript`/`HasActiveStatus("SNEAKING"|"INVISIBLE")`; эталон движка `brawl_Utils.isVisible` (статусы, без геометрии). Shroud — туман карты, не восприятие. Серверный viewshed отложен. → открытый вопрос к прототипу (семантика/клиент-сервер/цена). См. `issues/01-perception-signal-api.md` + `research/01-perception-signal-api.md`.
- **perception-emitter-prototype** (prototype, ticket `02`, 2026-09-20): черновой фильтр живьём. **В бою сырых Osi-предикатов хватает** (`CanSee` жив, всё честно `visible`). **В эксплорейшне — нет:** `CanSee=0` везде, `IsInvisible`≈«скрыт от камеры», `HasLineOfSight` — коллизия без конуса/спины; засада утекла как `known`, известные NPC ложно срезаны. **Решение по развилке №1:** два разных сенсора — **эмиссия `visible` = глаза игрока (камера/фог)**, **гейты экшенов `feasible` = механика движка** (`CanSee`/LOS/статусы). Фолбэк: камера-фог недоступна в client-Lua → фрустум+LOS от камеры; иначе — документированная слепая зона. Стоимость эмиттера 11–15 мс/тик. См. `issues/02-perception-emitter-prototype.md`.
- **perception-contract** (grilling, ticket `03`, 2026-09-20): контракт зафиксирован — **`spec.md` rev 2, бинарная модель**. Два сенсора: эмиссия = B (камера/фог, «движок отрисовал игроку»), экшены = A (механика). **Память вырезана**: `known`/`last_seen` не входят в v1 (стейл-позиция врёт); виден → с текущей позицией, не виден → нет. Бой: участники всегда в `state.enemies` (игра раскрывает инициативой + картой), невидимый участник — силуэт на истинном месте. `seen_by` удалён. Не-визуальные каналы (шум/запах) — документированная слепая зона. На стенд: камера-фог в client-Lua, `StartSightEvents`, дебаунс. См. `issues/03-perception-contract.md`.
- **action-gating** (grilling, ticket `04`, 2026-09-20): **перцепт-гейт на роутере уже выполнен по построению** — роутер отклоняет действия по сущности, которой нет в эмитированном стейте (`TargetMissing`); в бинарной модели «в стейте ⇔ в поле зрения». Код отказа НЕ меняем (юзер: переиспользовать `TargetMissing`), правим только дефолтное сообщение под правило восприятия. Матрица: entity-цели гейтятся зеркалом (attack — `enemies`, cast/move — `enemies`∪`allies`, interact/loot — `objects`, партия никогда); без цели (`end_turn`, `rest`), `travel_to` (кураторский disclosed), позиционный AoE — не гейтятся (v1). **Мод-side авторитетный перцепт-гейт** — дочерний тикет `04b` (Lua + стенд; target ∈ party ∪ emitted-this-tick → отказ `no_perception`). См. `issues/04-action-gating.md`, `issues/04b-mod-perceptual-gate.md`.
- **cast-projectile-location** (prototype, ticket `06`, 2026-09-21): «снаряд у кастера / каст не туда» у игровых целевых кастов. **Решение:** построение запроса НЕ баг (от эталона `tinybike/Brawl` Actions.lua — структурно идентичны: FromClient, Ext.Entity-цель, field_A8); механизм №1 = **отсутствие pre-валидации дальности/LOS**: вне радиуса движок отклоняет цель запроса (CastSpellFailed) и **сам подбирает ближайшего кандидата** (live: witch bolt с 22 м при радиусе 18 м → «луч в труп»). Механизм №2 (in-range: sneak→у кастера, bless→на себе) — открыт, требует чистого контролируемого бенча. **Изменение в мод:** pre-валидация `no_range`/`no_los` как у brawl (дистанция по spell.Range/weapon.Range + `Osi.HasLineOfSight`), позиционные касты НЕ гейтим; `success:true`/`cast_failed` трактуем как «событие исполнилось/нет», не как факт попадания. См. `issues/06-cast-projectile-location.md`.
- **acceptance-and-bench** (grilling, ticket `05`, 2026-09-20): приёмочный план (paper) зафиксирован под бинарную модель — сценарии P1–P8 «вход → ожидаемый исход» (засада не эмитится / LOS / исчезновение / боевой ростер / отказ по невидимой цели / невидимый в кадре / партия / AoE-точка), доказательство = снапшоты + SE-лог + серийные инжекты, **порог стоимости ≤ 20 мс/тик** (медиана 5 прогонов), критерии «спек готов к реализации» (research §8 → тикеты B/A + 04b зелёные). Строки черновика добавлены в `docs/manual-regression-checklist.md` (раздел Perception). Выполнение — следующий заход со стендом. См. `issues/05-acceptance-and-bench.md`.

## Not yet specified

- Позиционный AoE под восприятием: точка удара вне восприятия, а по ней стоят сущности — как себя вести (в v1 не гейтится; проверка «точка в поле зрения» — после B-модуля).
- Зеркало `bonus_action`/`use_item` целей на роутере (пока мод гейтит; 04b решит — нужно ли роутеру).
- Память/`known` (отложено из v1): если вернуть «помним, что видели», то БЕЗ стейл-позиций — только факт существования (вопрос: полезно ли без позиции).
- Стоимость LOS/рейкастов на каждом тике при многих сущностях; бюджет и кэш.
- Тонкости модели обнаружения/слуха (что именно снимает скрытность, как шум/open-door влияет).
- Как восприятие влияет на `turn_order`/инициативу: скрывать ли невоспринятых участников боя из порядка хода.
